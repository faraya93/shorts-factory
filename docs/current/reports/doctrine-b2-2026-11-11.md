## 6. Deviations from the report, with reasons
1. **P6 enforcement was built here, not deferred to a Sonnet code block.** B2 is "doctrine", but a doctrine that says "the runner refuses an unstamped unit" while the code does not would be false live text, and the report's "before production resumes" list needs that refusal with no block owning it. The code is small and tested.
2. **The schema and final-render refusal applies from production 025, not to every production.** 001-024 predate the stamp and most have no Opus proof; gating them would break finished work. The runner refuses every unit regardless of number, which covers revived entries.
3. **The stamp is guarded by permissions plus doctrine, not by cryptography.** Runner sessions are denied Write/Edit of `provenance.json` and the stamp command. The heredoc hole the report found under P5 (`.venv/bin/python - <<EOF` can write any file) also covers this file until block B3 closes it.
4. **P7 also got a schema check,** beyond the doctrine sentence: a rule with no check is the failure the report diagnosed. The reader prompt ("the single object") is named as a root cause but left unchanged, because changing it changes the measurement; the owner's boundary keeps reader isolation and thresholds fixed, and a prompt change would need its own calibration.
5. **P10 is doctrine only** (no code counter in `gate.py`). Enforcement in code would touch the gate; B1's `build/reader-ledger.jsonl` makes an audit or a later counter possible.
6. **P9 says "from proof readings where a proof exists".** P8 proof units are blocks B4/B5; until then the fallbacks come from the audit.
7. **P14: a 22 KB budget instead of about 25 KB.** The rewrite reached 20.1 KB, so the test keeps the margin small and regrowth trips early. "Section-scoped reads" are implemented as a tool plus instructions, not a hook.
8. **`return_topic.py` no longer creates folders,** so it no longer imports `tools/new_production.py`; standbys are created by the creative session with that tool.
9. **The developed standby buffer's depth is a standing formula** (expected returns of the next batch at the latest measured return rate), not a fixed number; filling it is B4.
10. **The batch's uncommitted record edits** (idea-bank rows, lens-decision and INDEX rows for the 025 return) were left uncommitted for B4 (P15). Only this block's hunks were staged.
