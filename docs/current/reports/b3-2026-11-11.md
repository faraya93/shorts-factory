## 4. Deviations from the report, with reasons

1. **The cap reads a runner-published file, not the transcript.** The report said the hook would read context size from the transcript. Measured live (claude 2.1.308): at PreToolUse the transcript holds no usage line for the current call yet (every hook call read 0; the lines appear after the tools run). The runner already parses each API call's usage from the session stream, so it writes the latest context to `SF_CTX_FILE` and the hook reads that. The transcript reader stays as a fallback (the larger of the two counts).
2. **Closing the hole went beyond heredocs.** The scan alone is best-effort (a string built by concatenation can slip past a literal check), and Write-then-run bypasses it entirely. So the same change adds the `SF_TOOLS_REV` script rule and the runner's hash check of the stamp. The stamp is now guaranteed by detection (batch halts), not by prevention alone. Residual: a session can still write files with `cat > f <<EOF`, which cannot then be run; and detection happens after the session ends.
3. **Callback always ends in a session when the package is built by code.** Before, a green verifier ended the unit with no session. Now there is one small fresh report-only session, as the report's design says (code builds, session writes the report). Cost: one small session per verified video (cached start about 23k).
4. **Defaults are judgement.** `SF_CTX_CAP` 200,000 (the report: "about 200k"); `SF_RESUME_MAX_CTX` 150,000 (the report: "small contexts", no figure). Session budget (12) is unchanged although handoffs make a 019-sized unit about 4 sessions plus the callback.
5. **`--max-turns`** stays unused (it does not exist in CLI 2.1.308, as the report found).
6. **Lens approval.** Doctrine edits (P4 bullet, "Runner session mechanics") were made under the owner's explicit block order with one session standing in; no separate lens session ran, as in B2. The record says so; the owner can ask for a lens re-read.
7. **`tools/*.sh` / `.py` of `tools/`, `factory/`, `tests/` changed after a batch starts do not run in that batch** (the rule compares with the starting commit). Fixing a tool mid-batch needs a runner restart. Chosen over a weaker rule.
8. **Preflight** with the new flags and hook (`run_productions.py --preflight`, after the code commit): 20 commands issued, 1 denial (the curl negative control), PASS.
