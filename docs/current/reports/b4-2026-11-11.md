## 5. Deviations from the report, with reasons

1. **P8 enforcement built here, not left to a code block.** A doctrine saying "a unit joins a batch only after its proofs pass" while the runner and `return_topic.py` ignore proofs would be false live text. This is the reason B2 gave for building P6's enforcement in a doctrine block. The code is small and tested.
2. **Proof scope is wider than "elements".** `proofs.json` also holds asset seals (declared library assets that are not `ready`: earth-globe, bird, microwave-oven) and the first `world` render-cost measurement (028 W1). An unsealed asset or an unmeasured environment blocks a unit just as an unread element does.
3. **022's new reading was specified, not taken.** The report says Opus never builds or reads proofs, and its P7 text gives the reading no block. N1 is B5's first job. Also changed: the hero route, to `code-primitive` with `microwave-oven`, because the oven is a geometric build and the gate had passed the hero with no library asset. This stales the frozen hero record, which is stated in 022's notes and proofs.
4. **026's staging moved from `cutaway` to `stage`.** With 019, 022 and 024 cutaway, a cutaway 026 would make four cutaways in the five productions 019-026 (format policy rotation).
5. **014: the "return to the bank" option**, with its last attempt converted into a proof, rather than re-developing a script first (lens row).
6. **Format-policy test amended,** not just made to pass by new data: returned units excluded, and one named historical run. B3's attribution of the failure was wrong (section 1).
7. **P12 tool plus generated index.** The report asked for a generated index; there was none, so it was built (`--check` reports staleness). It is not wired into a test, so adding a rig does not fail the suite.
8. **Proof readings are recorded in `proofs.json`, not in a production's gate records.** `blind_read.py --record element` needs a scene-designed `scenes.json`, which these units do not have yet. B5 needs a recording path into `proofs.json` (open item 1).
9. **Durations** were estimated at the channel's measured 2.9 words/s. 029 was trimmed from 215 to 207 words to stay clear of the verifier's 75 s ceiling.
