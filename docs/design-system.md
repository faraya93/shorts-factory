# Channel design system — ADOPTED IDENTITY: CORAL (owner decision 2026-10-28, provisional)
Status: **Coral is the adopted identity. Papel is superseded and kept as a named preset.** The identity is PARAMETERS in one place, not code.
History (frozen records, not the current system): `docs/design-system-round1-superseded.md` (celeste proposal), `docs/design-round2.md`, `docs/marketing-verdicts.md`, `docs/colour-panel.md`, `docs/hard-constraints.md` (the constraint table and the Coral derivation).

## 1. Where the identity lives (single source of truth)
**`channels/umbrella-es.yaml`**, blocks `identity` and `render` (the existing channel config was promoted; `factory/directions.json` was merged into it and deleted).
| consumer | how it reads the config |
|---|---|
| Editor subtitle/overlay themes, end-card mark (`factory/overlays.py`, `factory/editor.py`) | `factory/identity.py` -> one text theme per preset (`overlays.THEMES[name]`); a production's `visual_identity.text_theme` names the preset |
| a production's embedded `visual_identity` (palette, background, unify) | generated by `identity.visual_identity_block()`; `python factory/identity.py apply productions/x/scenes.json [--preset N]` embeds it and sets `identity_preset` and `render_args` |
| code3d (stage gradient, plinth, board, accent, error, halo/rim; render profile) | Blender has no PyYAML: the render driver (`factory/code3d_render.py`) calls `identity.export_json()` -> `build/identity-export.json` (generated, git-ignored) and passes `identity=<path>`; `code3d/lib/pipeline_config.py` + `looks.py` read it |
| brand tools, constraint table | `tools/brand_mark.py`, `tools/constraints.py` import `factory/identity.py` |
**Which block a future switch edits:** change `identity.active` in `channels/umbrella-es.yaml` (or edit one preset's values), then re-render. A colour change is a preset edit plus a re-render, never a code change. `visual_identity` in the same file holds only the non-colour fields (lighting words, materials, the Editor `unify` pass, QA tolerance): do not put colours there.
Preset fields: `stage.top/bottom` (screen-space gradient), `plinth` (what every hero stands on), `board` (gear-rig backing board), `accent`, `error`, `annotation`, `subtitle.{mode,ink,outline,spoken_box,spoken_text,emphasis}`, `mark.{body,inner,accent}`, `lighting` (`studio` | `dark-stage`). Shared `identity.neutrals` (passive greys). Hero colours (yellow tape, red thermos, blue gears) are NOT identity; they live with the rigs.
Presets in the file: **coral (active)**, papel, esmeralda, violeta, mandarina, rosa, lima, fucsia, cobalto, frambuesa, celeste, reference-dark, dark-teal. `reference-dark` and `celeste` are also what the legacy text-theme names `dark` and `light` resolve to, so frozen productions render unchanged.

## 2. The identity: CORAL
| role | value |
|---|---|
| stage (screen-space gradient, lighter behind the caption band) | **#FEA181 -> #EC9172** (light warm coral-salmon, L* 72) |
| plinth (every hero stands on it; separates white, yellow and silver bases) | ink **#1D1B2E** |
| board (gear rig) | #D1795C (derived: stage bottom, 9 L* darker) |
| accent = the active quantity | deep teal **#0A5C6B** |
| error mark | wine **#7A0019** |
| annotation (tags, leaders, brackets, counters' strokes) | ink #1D1B2E |
| subtitles | ink words (#1D1B2E) with a white 4 px outline; the spoken word reversed in an ink box with white text; key-word box outline in the accent |
| mark | body ink, inner cream #FFF3E0, accent teal (cut-corner mark: `tools/brand_mark.py`) |
Measured (docs/hard-constraints.md, thresholds C0-C4): text 7.1:1, spoken box 16.8:1, accent 3.2:1, error 4.8:1; distance from a white UI 28 and from a black UI 60 (CIEDE2000); 3 of 36 heroes under 20 (orange tool, light skin, organ pink).
### Coral's two production rules
1. **Body-family heroes stand in a cream cutaway plate.** Skin, organs and pinks are within 13-16 of the stage, so every body/medical hero is shown inside a cream (#FFF3E0) cutaway plate with a thin accent-teal frame (the doctrine's glass-plate-and-frame cutaway), so the local contrast is cream-versus-hero, not stage-versus-hero. Never a pink, orange or skin-toned hero on the bare stage. (Rig support for the plate is not built yet; it is a required element of the first body-family production.)
2. **The accent is dark, so its glow reads by HUE, not brightness.** At 3.2:1 the teal is a shape-and-hue signal: (a) the active quantity is always carried by a SHAPE (a filled bar, a ring, a marked part), never by bloom or "glow" alone; (b) overlays and counters that mark the active quantity draw the accent as a fill or ring WITH an outline in the theme's stroke colour (the Editor now outlines the "ok" ring; the slim bar already has a plate edge); (c) the accent is never used for text (counters, tags and subtitles stay ink: 7.1:1); (d) a 3D emissive in the accent colour is kept at full strength but nothing may depend on it being brighter than the stage; (e) never place the accent beside another teal/green hero without the ink plinth between them.

## 3. Typography, overlay sizing and framing (unchanged from the adopted round-1 rules; Montserrat ExtraBold, SemiBold for unspoken words)
Subtitles 57 px, 4 px outline, spoken word in a box, max 4 words, centre y = 0.24 H; counter (mono) 80 px (96 proposed), tag 34 px ALL-CAPS tracked, chip 44 px, leader 3 px; marks 120 px. Safe zones (1080x1920): the hero and every graphic inside x 0.10-0.90, y 0.28-0.75; counters at y <= 0.72; nothing essential below y 0.75 or in the right 18% below y 0.45; caption band 0.15-0.30. First-frame rule: the hero in real colours on the plinth by frame 0, the false-belief contrast visible by t = 2 s. Shadows are not used on text. The grain pass (`unify.grain`) is mandatory (it hides the 8-bit gradient steps of the stage).
Closing: no appended end card and no CTA graphic (owner 2026-10-28; `docs/cta-endcard-audit.md`); the spoken share ask stays.

## 4. Render stack (adopted default, owner 2026-10-28): the tuned profile
`render.profiles.tuned` in the same config: **OIDN on the GPU, adaptive threshold 0.04, minimum 24 samples, ceiling 128, Persistent Data on, transmission and volume bounces 0, bounce limits 3/4/8, Fast GI OFF.** EEVEE stays the draft engine. Per-scene-type exceptions live in `render.scene_types` / `render.scene_type_profiles` (see `docs/render-profile-rider.md` for the outcome of the cross-section and exploded-housing bench). `profile=previous|tuned` and `samples=` override from the command line.
Expected cost of a Coral production: about 2.5-3.5 s/frame (3-scene tuned bench 2.87; the full-scene Coral clip rendered at 2.79 s/frame), i.e. about 1.5-2 h for a 1,700-1,900-frame video, against 4.4-6.4 h for the old Papel renders.

## 5. Audit: what was de-hardcoded, and what is kept on purpose
De-hardcoded (now read from the config): `factory/overlays.py` (the "dark"/"light" theme tuples and the per-direction loader; end-card colours), `factory/editor.py` (subtitle colour constants and the "light" theme), `factory/visual_identity.py` (the default lift curve), `code3d/lib/looks.py` (every stage/plinth/accent/error/halo/rim literal of the A/E/CEL/D0 looks), `code3d/lib/gear_rig.py` (plinth and board), `code3d/lib/tape_rig.py` (the Cycles sample/adaptive/bounce numbers), `tools/brand_mark.py`, `tools/constraints.py`, `factory/directions.json` (merged and removed), and the colour part of `channels/umbrella-es.yaml: visual_identity` and `style.base` (now Coral wording; the dark text is kept as `reference_dark_v1`).
Kept on purpose: hero colours (`tape_rig` housing/blade/boot via `looks.real_colours`, gear cobalt/deep blue, test thermos); device-UI colours of the CTA phone mock-up (`overlays.TEAL0`...); the grey legacy-rig material defaults and halo/rim defaults in `tape_rig.py` for renders run without a look; frozen era code (`dark_rig.py`, `lace_world.py`, `boot_world.py`, `cartoon.py`, `props.py`, `stage.py`, `spike_*`, `scene_02.py`) and frozen experiment scripts (`tape_look.py`, `tape_look2.py`, `thermos_validate.py`, `bench_gear.py`), which reproduce earlier records. `tests/test_identity.py` fails if the ACTIVE preset's own colours reappear as literals in `factory/`, `code3d/lib/` or `tools/`.
Productions already rendered (huincha-de-medir, ...-papel, engranajes-papel) embed their own `visual_identity` and are not touched; their re-render in Coral is a separate job.

## 6. Verification (2026-10-28)
- Test suite: 8 + 12 + 4 + 1 + 15 + 13 tests pass (`tests/test_identity.py` is new: presets become text themes, the legacy theme names resolve to the same values as before, `apply` embeds the identity into a scenes.json, the Blender export carries presets and render profiles, and no active-identity colour is hard-coded in `factory/`, `code3d/lib/`, `tools/`).
- Stills rendered THROUGH the config (`look=active identity=<export>`, no preset named in code): the tape (scene 3 frame 130) and the gears (scene 3 frame 230) in Coral; and the same tape still after exporting the config with `--preset papel`, which turns it cream with no code change (`docs/design-system-assets/coral-verify/`).
- End to end: the render driver on a throw-away production (`productions/pilot/coral-verify`, embedded with `identity.py apply`) rendered gears scene 7 (155 frames, 32-sample ceiling) with the Coral look and the tuned default, 2.21 s/frame, no look or profile named on the command line.
- Observations: the 3D emissive teal renders as a bright cyan (lighter than the #0A5C6B swatch), so in 3D the accent reads by hue and brightness, in overlays by hue and shape; the gear board (derived 9 L* darker than the stage bottom) almost merges with the stage and may need a darker derivation when the gears are re-rendered in Coral.
- Expected cost of a Coral production under the adopted default: 2.5-3.7 s/frame (tuned bench 2.87 on scenes 1/3/5; full Coral scene clip 2.79; cross-section 2.93 and exploded housing 3.64 in the rider) = about 1.4-2.0 h for 1,700-1,900 frames.
